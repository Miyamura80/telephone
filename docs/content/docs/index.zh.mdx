Telephone 是一个充当交换机的 MCP 服务器。两个 MCP 客户端（例如两个 Codex CLI
实例，或 ChatGPT 与 Codex）连接到它，由它在两者之间转发双向对话，中间不需要人工复制粘贴。
一个服务器可以承载多条具名的 **line（线路）**，因此可以同时进行多个通话。

六个通话工具通过 `/mcp` 提供：`dial`、`answer`、`say`、`listen`、`get_messages`
和 `hang_up`。完整说明见 [Tools](/docs/mcp/tools)。

## 示例：代理之间的 bug 报告

一个 **caller（呼叫方）** 代理在使用某个 CLI 工具时遇到 bug。它无法修改该工具，
但另一处的 **implementer（实现方）** 代理拥有该工具的代码库。无需人工在两者之间传话：

1. 呼叫方通过 `dial` 拨通一条线路，并描述故障。
2. 实现方 `answer` 接听，然后用 `say` 提出诊断问题（使用了哪些参数、哪个版本、完整的错误信息）。
3. 呼叫方在自己的环境中逐一回答。
4. 实现方修复 bug，并请呼叫方重试。
5. 呼叫方确认修复成功，并以 `resolved: true` 调用 `hang_up` 挂断。

`dial` 和 `answer` 会返回一个 `seat` 令牌，双方在之后的每次调用中都要传入它。
通话在达到 `max_turns`（默认 60 条消息）或静默超过 `idle_timeout_s`（900 秒）后也会自动结束。

## 工作原理

```text
  caller agent                  Telephone                  implementer agent
  (Codex CLI)                 (one server)                 (ChatGPT or Codex)
 +-------------+           +-----------------+           +------------------+
 |             |  MCP      |  line "bug-123" |   MCP     |                  |
 |  say/listen |---------->|  +-----------+  |<----------| answer/say       |
 |             |<----------|  | transcript|  |---------->|                  |
 +-------------+  held     |  +-----------+  |  signed   +------------------+
                  open     |  line "deploy"  |  webhook
                  until    |  line ...       |  (MCP Events)
                  peer     +-----------------+  wakes the
                  speaks                        client
```

每一方都需要知道对方何时发言，Telephone 为此提供两种投递方式：

- **长轮询（Long-poll）**，适用于 Codex 等代理 CLI：`dial`、`answer`、`say` 和 `listen`
  会在服务器端保持工具调用最多 `wait_s`（默认 50 秒，上限 540 秒），一旦对方发言就立即返回，
  因此代理始终在自己的工具循环中"保持通话"。
- **MCP Events**，适用于 ChatGPT 等事件驱动的客户端：服务器声明 `io.modelcontextprotocol/events`
  扩展（草案规范），并在对方发言时发送带签名的 webhook（`line.message`、`line.ended`）唤醒客户端。
  同一个 `/mcp` 同时支持 2025 年的握手方式和 2026-07-28 协议。

在交换机之下是一个共享的服务注册表，以三种方式对外提供：CLI（`telephone`）、
MCP 端点（`/mcp` 上的 streamable HTTP），以及带认证的 REST API。
