Telephone は交換台として機能する MCP サーバーです。2 つの MCP クライアント（たとえば
2 つの Codex CLI インスタンス、または ChatGPT と Codex）が接続し、Telephone がその間で
双方向の会話を中継します。人間がコピー＆ペーストで仲介する必要はありません。1 つのサーバーで
複数の名前付き **line（回線）** を扱えるため、複数の通話を同時に進められます。

## 例: エージェント間のバグ報告

**caller（発信側）** エージェントが CLI ツールを使っていてバグに遭遇します。発信側はツールを
変更できませんが、別の場所にいる **implementer（実装側）** エージェントはそのツールの
コードベースを持っています。人間がメッセージを取り次ぐ代わりに:

1. 発信側が回線に `dial` し、障害の内容を説明します。
2. 実装側が `answer` で応答し、`say` で診断のための質問をします（使ったフラグ、バージョン、エラー全文など）。
3. 発信側は自分の環境から各質問に答えます。
4. 実装側がバグを修正し、発信側に再試行を依頼します。
5. 発信側が修正を確認し、どちらからでも `hang_up` で通話を終了できます。

## 仕組み

```text
  caller agent                  Telephone                  implementer agent
  (Codex CLI)                 (one server)                 (ChatGPT or Codex)
 +-------------+           +-----------------+           +------------------+
 |             |  MCP      |  line "bug-123" |   MCP     |                  |
 |  say/listen |---------->|  +-----------+  |<----------| answer/say       |
 |             |<----------|  | transcript|  |---------->|                  |
 +-------------+  held     |  +-----------+  |  signed   +------------------+
                  open     |  line "deploy"  |  webhook
                  until    |  line ...       |  (MCP Events)
                  peer     +-----------------+  wakes the
                  speaks                        client
```

双方とも、相手がいつ発言したかを知る必要があります。Telephone はそのために 2 つの配信方式を提供します:

- **ロングポーリング（Long-poll）**: Codex などのエージェント CLI 向け。`say` と `listen` は
  サーバー側でツール呼び出しを保持し、相手が発言した時点で返ります。エージェントは自身のツール
  ループの中で回線につながったままでいられます。
- **MCP Events**: ChatGPT 向け。メッセージが届くと、サーバーが署名付きの webhook を送って
  クライアントを起こします（ドラフト仕様）。

交換台の下には共有のサービスレジストリがあり、CLI（`telephone`）、MCP エンドポイント
（`/mcp` の streamable HTTP）、認証付き REST API の 3 つの形で公開されます。
