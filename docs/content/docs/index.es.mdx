Telephone es un servidor MCP que funciona como centralita. Dos clientes MCP (por
ejemplo, dos instancias de Codex CLI, o ChatGPT y Codex) se conectan a el, y
Telephone transmite una conversacion bidireccional entre ambos sin que nadie
tenga que copiar y pegar mensajes. Un solo servidor aloja muchas **lines**
(lineas) con nombre, asi que pueden coexistir varias llamadas.

Seis herramientas de llamada hacen el trabajo sobre `/mcp`: `dial`, `answer`,
`say`, `listen`, `get_messages` y `hang_up`. Consulta
[Tools](/docs/mcp/tools) para la referencia completa.

## Ejemplo: un reporte de bug entre agentes

Un agente **caller** (quien llama) usa una herramienta CLI y encuentra un bug.
No puede modificar la herramienta, pero un agente **implementer** (quien
implementa) en otro lugar tiene el codigo fuente. En lugar de que una persona
pase los mensajes entre ellos:

1. El caller hace `dial` a una linea y describe el fallo.
2. El implementer responde con `answer` y hace preguntas de diagnostico con `say` (que flags, que version, el error completo).
3. El caller responde cada pregunta desde su propio entorno.
4. El implementer corrige el bug y le pide al caller que vuelva a intentarlo.
5. El caller confirma la correccion y hace `hang_up` con `resolved: true`.

`dial` y `answer` devuelven un token `seat` que cada lado pasa en cada llamada
posterior. Una llamada tambien termina sola al llegar a `max_turns` (60 mensajes
por defecto) o tras `idle_timeout_s` (900 s) de silencio.

## Como funciona

```text
  caller agent                  Telephone                  implementer agent
  (Codex CLI)                 (one server)                 (ChatGPT or Codex)
 +-------------+           +-----------------+           +------------------+
 |             |  MCP      |  line "bug-123" |   MCP     |                  |
 |  say/listen |---------->|  +-----------+  |<----------| answer/say       |
 |             |<----------|  | transcript|  |---------->|                  |
 +-------------+  held     |  +-----------+  |  signed   +------------------+
                  open     |  line "deploy"  |  webhook
                  until    |  line ...       |  (MCP Events)
                  peer     +-----------------+  wakes the
                  speaks                        client
```

Cada lado necesita saber cuando ha hablado el otro, y Telephone ofrece dos modos
de entrega para ello:

- **Long-poll** para CLIs de agentes como Codex: `dial`, `answer`, `say` y
  `listen` mantienen abierta la llamada a la herramienta hasta `wait_s` (50 s por
  defecto, 540 s como maximo) y regresan en cuanto el otro lado habla, asi el
  agente sigue en la linea dentro de su propio bucle de herramientas.
- **MCP Events** para clientes basados en eventos: el servidor anuncia
  `capabilities.events` y envia un webhook firmado (`line.message`,
  `line.ended`) que despierta al cliente cuando el otro lado habla
  (especificacion en borrador). Que ChatGPT negocie events de extremo a extremo
  depende todavia de que el servidor migre al MCP Python SDK v2 (protocolo
  2026-07-28).

Debajo de la centralita hay un registro de servicios compartido expuesto de tres
formas: una CLI (`telephone`), el endpoint MCP (streamable HTTP en `/mcp`) y una
API REST autenticada.
